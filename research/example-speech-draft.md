# Safer launch process

Audience: the product team
Smallest useful outcome: choose one next experiment

## Orient
We need to reduce launch surprises without slowing every decision.

## Purpose Attention Example
The problem is that the same approval path treats a small copy change like a safety-critical release. Our smallest useful outcome is one risk-based pilot.

## Question Redefinition
The question is not whether we can remove review. It is which changes need which review, and who owns that decision.

## Evidence Gap
We know the current path adds delay. We do not yet know whether the pilot catches the failures we care about. We will test it on the next three releases and record misses.

## Hands Off
The release owner makes the final decision. I can provide the checklist and the results. This proposal does not remove the owner's responsibility.

## Close
The next step is to run the bounded pilot, then return with the misses and the evidence. The claim is limited to this team and this test.

Listener check: Can you say what changes, who decides, and what remains untested?
Boundary check: This is a candidate practice structure, not proof that the process will work.
