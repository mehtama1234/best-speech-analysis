## The five-minute route

1. Open the [learner-card browser](corpus-learner-card-inventory.html).
2. Choose **Start a practice card**, or filter by a situation:
   opening, closing, question, answer, story, disagreement, repair,
   qualification, action, credit or another communication job.
3. Read the card's exact caption evidence. Do not begin with the celebrity or
   the phrase; begin with the listener problem and the observed move.
4. Inspect the exact phrase handles. Rewrite the structure in your own words,
   relationship and level of certainty. A phrase such as `but`, `I think`,
   `we need to` or `for example` is not a technique by itself.
5. Open the nearby delivery and movement candidates only to inspect timing,
   audio, framing and visible geometry. Do not infer confidence, emotion,
   honesty, intent or persuasion from a proxy.
6. Try the card in a low-stakes situation, ask for a listener restatement,
   then use the local practice log to record the wording, delivery mode,
   non-fit or safety issue and next revision.

## Six moves worth trying first

These are the most reusable cross-job hypotheses in the current corpus synthesis.
They are practice candidates, not proven best practices:

1. **Orient before detail:** situation → stake → route.
2. **Answer, then frame:** direct answer → useful context → condition or limit.
3. **Make the abstract inspectable:** claim → bounded example → interpretation → boundary.
4. **Make change visible fairly:** earlier view → what changed → present view → genuine overlap.
5. **Turn credit into responsibility:** contribution/problem → accountable actor → bounded action → support and consent.
6. **Close with a retrievable point:** takeaway → next step or uncertainty → release the turn.

For each move, write one sentence in your own words, deliver it twice while
changing only one delivery choice, and ask a consenting listener for the
takeaway, unresolved point and any pressure or burden. The [findings
catalog](corpus-findings-catalog.md) contains the retained examples and
boundaries; the [repeatable-patterns guide](repeatable-communication-patterns.md)
explains the cross-job synthesis.

## Choose the right job

| If you need to… | Start with… | Basic structure |
|---|---|---|
| orient someone | `opening` | situation → stake → route |
| end clearly | `closing` | takeaway → limit/next step → release |
| disagree | `contrast_or_disagreement` | earlier frame → change → present view → overlap |
| correct yourself | `repair_or_self_correction` | said X → why incomplete → accurate Z |
| make an idea concrete | `example_or_case` | claim → case → return to claim → boundary |
| tell a personal story | `story_or_personal_experience` | bounded scene → illustration → what it cannot prove |
| answer pressure | `answer_or_response` | literal answer → useful frame → condition |
| ask well | `question` | specific question → context → answer/opt-out path |
| state uncertainty | `qualification_or_boundary` | claim → evidence/condition → what changes it |
| request action | `call_to_action_or_audience_role` | problem → actor/action → support, consent, limit |
| acknowledge work | `credit_or_acknowledgment` | contribution → result → what remains owed |
| move between points | `transition_or_structure` | close point A → name relation → enter point B |

The remaining jobs—definition, callback, humor, persuasion and reflection—are
in the same browser and in the [learner field guide](learner-field-guide.md).

## What to copy—and what not to copy

Copy the decision structure, not the speaker's identity, accent, status,
biography, trauma, body language or certainty.

For every attempted form, answer four questions:

- What listener problem was this trying to solve?
- Which exact words or sequence made the move visible?
- What condition, evidence, consent or accessibility limit applies?
- What would count as a non-fit or an alternate explanation?

Use the phrase inventory as a retrieval tool. It contains 8,062 exact handles
inside the full learner-card inventory, but recurrence is not proof of intent or
effectiveness. Read the surrounding caption context before adapting a form.

## A complete practice attempt

Situation: a colleague asks why a project changed direction.

1. **Ordinary version:** answer naturally in 60–90 seconds.
2. **Adapted version:** acknowledge the earlier plan, name the evidence that
   changed your view, state the current plan and preserve one real overlap.
3. **Listener check:** ask, “What changed, what do I believe now, and what is
   still uncertain?”
4. **Revision:** keep the structure only if it made the change easier to
   understand without caricaturing the earlier view.

For a personal story, replace private disclosure with a hypothetical or public
example when needed. For an action request, name the owner, resources,
consent path and limit. For a question, make declining or asking for
clarification possible.

## What the system can and cannot currently prove

It can provide full-context transcript evidence for all 395 project-generated,
single-pass full-context reviewed videos,
exact retained wording, provisional communication jobs, repeatable forms,
practice prompts, phrase retrieval, local delivery proxies and manual-review
queues.

It cannot yet prove that a pattern is universally effective, that a speaker
intended the inferred function, that a delivery measurement has a social
meaning, or that a learner/listener outcome improved. Independent function,
recurrence, counterexample, delivery, learner and listener review remain
separate gates in the [end-to-end acceptance matrix](end-to-end-acceptance-matrix.md).

## To finish the evidence gates

The repository is ready to receive, but does not invent, the remaining records:

- Independent interpretation: use the [blinded review packet](blinded-review-packet.html), then validate and reduce the export.
- Delivery/nonverbal review: use the [395-item delivery workbook](full-corpus-delivery-review-workbook.html), preserving `indeterminate` and `not_available`.
- Counterexamples: use the [counterexample workbook](communication-job-counterexample-workbook.html), including `no_candidate_found` where appropriate.
- Learner teachability: run the consented [learner protocol](validation-handoff.md) and validate the pseudonymous export.
- Listener outcomes: independently review and lock the matched stimuli before running the blinded listener protocol.

The [validation handoff](validation-handoff.md) contains the schemas, validators,
adjudication tools and claim boundaries. Until those records exist, use the
current materials as transcript-derived learning hypotheses and inspection aids.
The [external-review launch manifest](external-review-launch-manifest.md) gives
the ordered eight-operation handoff, dependencies and validators for collecting
the missing records without changing their claim status.
